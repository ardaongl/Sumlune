# Money & Currency Model

ADR-0010 ve ADR-0011: para temsili, rounding, wire ve FX posting Accepted (ürün sahibinin teknik detay yetki devri). Ücretsiz sağlayıcının kesin seçimi ve teknik uyum Pending.

## Kesin para temsili
Money: currency code + minor unit integer; ISO 4217 exponent 0/2/3 gibi farklı olabilir (JPY/TRY/KWD). UI locale-aware string parse, fazla basamakta açık validasyon; float * 100 yok. Örnek 125,50 TRY → 12550. SQLite signed INTEGER; JS bridge için abs(minor) ≤ 9007199254740991. Girdi, aritmetik ara sonuç, aggregate ve çıkış kontrol edilir. Normal safe integer işlemleri, gerektiğinde BigInt ara hesap; saklama sınırını aşan kayıt sessiz yuvarlanmaz. JSON/native sınırında minor unit canonical decimal integer string, adapter güvenli INTEGER'e dönüştürür. Eski kod olmadığı için migration yok. BigInt doğrudan JSON'a verilmez. Decimal.js dönüşüm için, kur TEXT pozitif canonical decimal string. Merkezi rounding HALF_UP (işaret simetrik, yarımda sıfırdan uzağa), kullanıcı gerçek tahsilatı girdiyse o tutar esas; taksit kalan kuruşu deterministik son takside (ADR-0012). Aynı tutarı tekrar tekrar dönüştürme yok.

## FX
Her rate base/quote, effective date, source (manual/provider), fetched_at ve decimal rate saklar. Otomatik oran referans kurudur, banka gerçekleşme kuru değildir. Manuel rate/tutar override; geçmiş snapshot immutable (düzeltme ayrı revizyon). Varsayılan TRY raporlama değişince orijinal kayıtlar değişmez. Tarihsel gelir/gider tarihsel kurla; mevcut bakiye son bilinen tarihli oranla; eksik dönüşüm açıkça incomplete ve özgün para gösterilir. Güncel kur geçmiş işlemi sessizce yeniden değerlemez. Yeni raporlama para birimi için tarihsel rate yoksa açık eksik durum ve tarihsel lookup/manual; kur uydurma yok.

FX posting: her para birimi kendi içinde dengelenir; farklı döviz transferinde gizli FX clearing sistem hesabı (currency başına). Örnek varsayımsal 3500 TRY → 100 USD, masraf yok: TRY banka -350000 minor, TRY clearing +350000; USD banka +10000, USD clearing -10000. 4 posting tek atomik journal. Gerçek miktarlar ve işlem kuru saklanır. Clearing kullanıcı nakit/gelir/gider/net worth toplamına dahil edilmez; varsa ücret ayrı expense posting. Gerçekleşmiş FX kazanç/vergi muhasebesi onaylı kapsam değil. Kur snapshot ve değerleme testleri gerekir. Dövizli kart alımında gerçekleşen kart borcu para biriminde iki posting (expense +, card liability -); özgün alışveriş amount/currency journal metadata ve kur snapshot olarak korunur. Gerçek banka tutarı bilinmiyorsa tahmini kayıt açıkça belirtilir veya aday incelemede bekler; gerçek borç tutarı uydurulmaz. Banka tutarı bilindiğinde düzeltme. Kur farkı resmi muhasebesi yok.

## Hibrit kur — Accepted davranış
Manuel giriş offline her zaman çalışır. Uygun ücretsiz servis ile güncel veya tarihsel oran alınabilir; güncel cache tarihli, stale etiketi, uygun tarihi olmayan oranı tarihsel gibi kullanma. Ağ hatası çekirdeği durdurmaz. Günlük/istek anında cache yenileme, arka plan polling/backend yok. Sağlayıcıya hesap/bakiye/işlem tutarı gönderme. Frankfurter aday (anahtarsız ücretsiz API, referans kurlar; https://frankfurter.dev/); TRY ve gerekli çiftler, lisans/attribution, yanıt hassasiyeti ve hata/limit davranışı entegrasyon öncesi doğrulanacak. Hizmetin gelecekte ücretsiz kalması garanti değil; manuel fallback bağımsız.

## Test adayları
TRY 125.50, JPY 100, KWD 1.234, hatalı input ve max-safe overflow; negatif iade rounding; SQLite/JSON round-trip; FX transferi iki currency dengesi; değişen kur ile geçmiş gider değişmemesi; eksik ve eski kur, raporlama para değişimi; gerçek banka kuru; ücretsiz kaynağın ulaşılamaması.

Referans: https://www.sqlite.org/datatype3.html ve https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/MAX_SAFE_INTEGER. Teknik kaynaklar kontrol edildi; cihaz, SQLCipher, native bridge ve canlı FX entegrasyonu test edilmedi.

## Saklama ve rapor ayrımı (Accepted)
exchange_rates yerel cache; journal_rate_snapshots işlemde kullanılmış pozitif oranı, yönü, tarih ve kaynağı değişmez olarak saklar. rate_decimal canonical decimal string, exponent formu yok; oran ters çevrilirken Decimal.js. Hesapta orijinal minor unit, dönüşümde tek hedef minor rounding. Raporlama para birimi değişince yeni tarihsel oran gerektiğinde tarihli cache/manual lookup; bulunamayan toplam eksik olarak işaretlenir. Düzeltme reversal'ı orijinal snapshot ile aynı değerlemeyi kullanır. Native/JSON minor string; CSV okunabilir major string + currency; kesin export schema PLAN-07. Kalan kuruşun taksite dağıtımı ADR-0012: floor(total/count), kalan son taksite; sıfır taksit yok. Cihaz round-trip, Decimal.js precision ayarı ve provider sözleşmesi test edilmedi.
